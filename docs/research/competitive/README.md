# docs/research/competitive/ — Competitor & adjacent-product research

**Purpose**: Analysis of products in or near GlaudeCode's space. The goal is honest
assessment — strengths, weaknesses, what to learn, what to avoid, where the layer test
applies.

**Per-doc structure**: every competitive research file SHOULD include:

1. TL;DR — what the product is, threat level, one-paragraph verdict
2. Feature inventory
3. Overlap matrix vs GlaudeCode's primitives and features
4. What's worth adopting (linked to ADRs if any are filed)
5. What to NOT do
6. Strategic implications
7. Honest uncertainties
8. Suggested follow-up

**Naming**: `kebab-case-product-name.md`. One file per product.

**Current files**:
- `pi.md` — Pi (`@earendil-works/pi-coding-agent`), 2026-05-18

**When to research a competitor**:
- A new product launches in or near GlaudeCode's space.
- Anthropic ships a feature that may overlap (Constitution Principle X — Differentiation Note).
- A user asks "have you looked at X?" and the answer is no.
