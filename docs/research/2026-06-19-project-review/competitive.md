# GlaudeCode — Competitive Landscape

> Produced by a multi-agent review (2026-06-19). Each competitor was researched independently and synthesized here.

GlaudeCode's bet: a **private, full-fidelity Claude Code cockpit on your phone** — conversation view (native chat from typed `getSessionMessages`) plus a one-tap raw terminal fallback — served over **your own Tailscale**, no vendor cloud, no account binding. Competing on **Claude Code integration depth**, not on being a better generic terminal or a neutral multi-agent meta-layer.

This document maps the field, scores where we win and where we're behind, and names the sharpest differentiation to lean into.

## Per-category analysis

### Category A — Mobile/remote control of a CLI agent (the direct contest)

These are the products that, like GlaudeCode, are about driving Claude Code (or a CLI agent) from your phone. This is where we live or die.

**Omnara** is the strongest mobile product and the closest threat on UX. Native iOS/Android apps, zero-config networking, voice-first two-way conversation, and **cloud handoff** that keeps the agent alive when the laptop sleeps. *Why it matters:* it directly targets our lid-closed/voice-first thesis and executes it well. *But its mechanism is its weakness* — it stores your messages, git diffs, and uncommitted code in **their Supabase cloud with no E2E encryption**, and the handoff literally copies your code into their environment. *Suggested direction:* lead positioning with "your code never leaves your machines; we have no server to leak," and match the offline-continuity benefit by keeping the engine alive on the user's own Mac over Tailscale (no cloud copy). Web Push for approval-needed/done is the table-stakes piece to ship (already pending). **Effort: push = M; keep-alive/power-assertion = M.**

**Warp Remote Control** validates the exact demand and is already shipped, but via a **cloud round-trip to Warp's servers + a Warp account** and an opaque shareable link — plus documented telemetry distrust. *Suggested direction:* contrast our own-Tailscale + scoped tokens + metadata-only audit log against Warp's cloud upload and Segment history. Make tap-to-go-mobile as instant as their `/remote-control` chip (QR pairing is good; WS4 seamless pairing closes the gap). **Effort: WS4 pairing = L.**

**Termius** is the sharpest reminder that **mobile terminal ergonomics are table stakes** — long-press-drag cursor, hold-Space-for-arrows, double-tap-Tab, a customizable hotkey bar. It actively markets the "run Claude Code from your phone" workflow (SSH+tmux, SFTP-upload-screenshots, port-forward preview). *Why it matters:* our gesture PUCK is judged against this bar, and the snippets feature (one-tap saved prompts) is a daily-use pattern we lack. *Suggested direction:* benchmark the puck against Termius (ensure arrows/Tab/Esc/Ctrl are all one-tap); add saved/canned Claude prompts fired one-tap from the phone. Our smart UPLOAD (auto `@`-reference) is already a step ahead of their manual SFTP — keep it native, don't regress. **Effort: snippets = S; puck parity audit = S.**

**Cursor / Windsurf** prove the demand from the IDE side but both ship **monitoring-grade or cloud-sandbox** mobile, not live coding on your own machine. Cursor itself admits "you are not going to rewrite a module from your iPhone." *Why it matters:* our conversation-view + raw-terminal-fallback on the phone is genuinely a different (and richer) product than a status dashboard. *Suggested direction:* own "real remote work, not a status board," and lean on approval fidelity — Cursor's cloud agents default to **no per-action approval**, ours inherit every native Claude approval through the terminal mirror.

**DIY (Tailscale+SSH+tmux)** is the incumbent we are explicitly replacing. It's full-fidelity and private by construction, but the friction (6+ moving parts), the raw-terminal-on-phone pain, the `--dangerously-skip-permissions` culture, the bolt-on ntfy push, and the undocumented lid-closed/keep-awake problem are exactly our wedge. *Suggested direction:* collapse the whole stack into QR pairing + auto-arm; own the keep-awake/power-assertion problem the guides ignore; ship native push tied to agent state; deliver ergonomic mobile approvals so users never disable permissions. **Effort: keep-awake = M; ergonomic approvals = already mostly built.**

**Conductor** is in this category only by adjacency — it has **no official mobile**, just a same-Mac Telegram hack. *Why it matters:* its parallel-worktree review/merge loop is a genuinely loved desktop UX we should make phone-drivable, since Conductor structurally can't. *Suggested direction:* expose a "workspace per task" surface (we have worktree/conflict/changes engine modules) and a lightweight mobile diff-review + one-tap merge; checkpoints/rollback is a concrete steal. Note: founder flagged diffs as low-priority — at minimum a **glanceable** mobile diff is worth it given Conductor, Cursor, and Zed all treat it as core. **Effort: mobile diff glance = M; workspace-per-task surface = L.**

### Category B — AI terminals & IDEs (the broader field, mostly desktop-bound)

These are not phone-first, but they set the quality bar and define the depth-vs-breadth axis.

**VibeTunnel** is the philosophical sibling: OSS, Tailscale-first, raw-terminal-in-browser. Its fatal gap — **mobile touch UX + no conversation view** — is precisely our wedge. *Why it matters:* it validates our transport choice and our decision to keep the raw `termPage` as a trust anchor. *Suggested direction:* keep the terminal fallback first-class; build the phone-first chat + gesture input it conspicuously lacks; offer safer-by-default security than its grab-bag of auth modes (no-auth and public Funnel are footguns). Borrow Git Follow Mode + asciinema recording (we already have worktree logic).

**Wave Terminal** shows the **integration-depth gap** cleanly: it just runs the CLI in a terminal block and paints **status badges** via hooks (gold bell = awaiting permission). *Why it matters:* its own users are asking for real `/ide`-level integration (issue #2791) it won't ship soon — exactly the depth our `ClaudeCodeAdapter` reading typed session messages provides. *Suggested direction:* steal the ambient badge pattern for the cockpit session list (we have richer typed data to drive it); lean into rendering the conversation as chat, which Wave explicitly does not do. **Effort: status chips in session list = S.**

**Zed** has the **most-requested-but-unbuilt** mobile feature (GitHub Discussion #49313: trigger agents, push on completion, review diffs from phone) — i.e. its own users are begging for our product. It's also a feature menu to steal: **Parallel Agents** (first-mover), live tool-call visibility, granular per-tool permissions. *Why it matters:* validation that the mobile bet is real and currently unserved by a leading editor; and Zed's **partial** Claude Code support (slash commands break) is a contrast we can win on. *Suggested direction:* surface "run N Claude sessions at once" across our PTYs/panes, drivable from the phone (lid-closed parallel runs beat Zed's desktop-bound version); make full slash-command/prompt/approval fidelity the headline. **Effort: parallel-session phone surface = L.**

**Ghostty** is the "do one thing perfectly" benchmark — it explicitly **refuses** mobile and punts to the community (Hoshi, $1.99). *Why it matters:* it's the discipline lesson — be ruthlessly the best at ONE thing (private full-fidelity Claude Code from your phone) and resist generic terminal-feature parity. Also: native rendering quality is table stakes, so our xterm.js mirror must never blank/feel slow (the mobile-mirror orphan bug already hit). *Suggested direction:* bank our differentiated surfaces before a funded team closes the gap; keep the engine clean/host-agnostic (libghostty's embeddability is the analogous moat to our Bun-sidecar PWA serving).

**Windsurf (→ Devin Desktop)** is a cautionary tale and a feature source: it's abandoning its own opinionated agent (Cascade EOL) for a generic ACP multi-agent command center, **validating our depth-over-breadth counter-bet**. Steal the visible "Running / Waiting-for-Review / Done" Kanban states for the cockpit session list; surface Codemaps-style structure (we have a graph module) in the drawer. *Suggested direction:* court burned Windsurf users who want something stable, private, and Claude-Code-native. **Effort: waiting-for-review state surfacing = S.**

## Positioning

### Where GlaudeCode wins (clear, defensible)

1. **Private / own-infra by default.** Omnara stores your code+diffs in Supabase (no E2E); Warp uploads session state to its cloud + requires an account; Cursor/Windsurf run cloud agents on vendor VMs; Termius routes through its cloud and isn't self-hostable. GlaudeCode runs the real Claude Code on the user's own Mac over their own Tailscale — **no vendor cloud, no account binding, nothing to leak.** This is the single sharpest wedge and the founder's exact thesis.
2. **A true phone cockpit that none of the desktop leaders have.** Zed, Wave, Ghostty, and Conductor have **no official mobile**; Cursor/Windsurf are monitoring/cloud-sandbox only. We drive the **actual running session** live.
3. **Conversation AND raw terminal on one device, one tap apart.** VibeTunnel/Blink/Termius/DIY are terminal-only (awful on touch); Omnara/Cursor are conversation/diff-only. Our `conversationPage` (native chat from typed messages) + one-tap `termPage` fallback is best-of-both — and the terminal inherits every approval/prompt variety for free.
4. **Claude Code integration depth.** Wave is badges-only; Warp/Zed/Windsurf wrap many agents generically; Termius/Blink/Ghostty are raw bytes. We go deep via the Agent SDK (typed `getSessionMessages`, cost/context/agent-state/conflict derivation) — Claude-native richness a generic wrapper can't match.
5. **A real, threat-modeled remote-access security model.** Scoped paired tokens (view < steer < terminal), per-pane arming, metadata-only audit log, rate limits, no-token-in-URL — versus VibeTunnel's footgun auth modes, the DIY `--dangerously-skip-permissions` norm, and cloud-relay account binding. This directly answers the "replace the company built-in remote" (account-bound + approval-desync) motivation.
6. **Observability-first.** Debug HUD + error surfacing + audit log answer the founder's "silent failure is the enemy" mandate; most competitors offer opaque cloud calls (Termius), PostHog-only analytics (Conductor), or no diagnostics at all.

### Where GlaudeCode is behind (be candid)

1. **Mobile terminal ergonomics maturity — Termius and Blink set a high bar.** Severity: **high.** A phone cockpit that's clumsier than Termius at arrows/Tab/cursor/gestures loses to "just SSH into Termius." Our puck is the right instinct but unproven against their decade of polish. *Action: benchmark + close gaps (S–M).*
2. **Native push / "agent needs you" notifications — not yet shipped.** Severity: **high.** This is the load-bearing piece that turns "monitor" into "get pulled in only when needed," and it's the async loop's whole point. Omnara, Cursor, and the DIY ntfy hack all have it; we have it pending. *Action: ship Web Push tied to approval-needed/done (M).*
3. **Lid-closed / keep-awake reliability is not yet a guaranteed feature.** Severity: **high.** Omnara's cloud handoff and DIY tmux both keep the agent alive; we own the Mac and can do better, but the engine-respawn orphan bug shows reliability isn't yet bankable. *Action: own power-assertion + guarantee session survives sleep/WebView/network drops; mosh-grade WS reconnect (M).*
4. **Onboarding friction vs zero-config relays.** Severity: **medium.** Omnara wins on "no SSH/port-forward/tunnel"; our Tailscale path is more private but riskier on friction. *Action: WS4 seamless pairing (QR + 30-day token + auto-arm) is exactly right — prioritize it (L).*
5. **Voice depth.** Severity: **medium.** Omnara ships voice-first two-way conversation as its headline; everyone else (Cursor/Termius/Blink) is dictation-only. Voice-first is the founder's thesis but not yet a differentiated, built feature. *Action: dictate-into-input as the minimum, then own the hands-free approve/deny loop nobody else has (M–L).*
6. **Distribution / momentum.** Severity: **medium (strategic, not product).** Cursor (~$2B ARR), Warp, Omnara (YC), Termius all have reach; we have one user (the founder). This is fine for now — the product is sharply scoped — but the differentiated surfaces (conversation-on-phone, voice, lid-closed) must ship before a funded team (Zed, Warp, Wave) closes the gap.

### The sharpest differentiation to lean into

> **"Drive your real Claude Code session from your phone — full fidelity, on your own infrastructure, with the agent still alive when your lid is shut. Your code never leaves your machine; there's no server to leak."**

This single sentence beats every competitor on its weakest axis simultaneously: Omnara/Warp/Cursor on **privacy + own-infra**; VibeTunnel/Blink/Termius/DIY on **conversation view + touch ergonomics + push**; Wave/Zed/Ghostty/Windsurf on **having any mobile product at all**; and the company built-in remote on **account-binding + approval-desync**.

To make it true, the non-negotiable next ships are: **(1) Web Push on approval-needed/done, (2) lid-closed/keep-awake as a guaranteed observable feature, (3) WS4 seamless pairing, (4) mobile terminal ergonomics at Termius parity.** Everything else (parallel-session surface, mobile diff glance, snippets, status chips) is high-value but secondary.
