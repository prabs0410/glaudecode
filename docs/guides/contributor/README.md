# docs/guides/contributor/ — Contributor how-tos

**Purpose**: How-tos for people contributing to GlaudeCode itself. Dev environment setup,
running tests, debugging the orchestrator, cutting a release, writing an extension.

**Naming**: `kebab-case-task.md`. First contributor-facing guides will likely be
`set-up-dev-environment.md`, `run-tests.md`, `write-an-extension.md`, `cut-a-release.md`.

**Audience**: a developer who has cloned the repo and wants to make a meaningful change.
Assume they will read the constitution and ADRs but not the entire codebase.

**Cross-references**: link liberally to the constitution (Code Quality Bar, governance) and
to relevant ADRs (especially ADR 0002 on extension conventions).
