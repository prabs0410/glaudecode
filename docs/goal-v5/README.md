## Context

GlaudeCode lets you drive your whole Mac terminal + Claude Code from your phone. **Phases 0–2 are done** (security footguns; view-only mirror; remote input with a `terminal` scope + per-pane arming + dual engine/Rust gates; a security review cleared it for personal use over your own Tailscale). This goal is the V5 plan's remaining **Phases 3–7**, decomposed for the loop to execute to completion.

**Decisions (locked):**
- **Order = me-first: 4 → 5 → 3 → 6 → 7.** Mobile-input polish (4) and Tailscale Serve / keep-awake (5) first (what improves *daily phone use*), then the public-release track: app-layer crypto (3), multi-OS (6), governance (7).
- **Human gates = build-all-then-checklist.** Build every automatable task across all phases in order; collect the human/external steps into the master checklist (below) rather than stalling. Two gates — the independent crypto review and the release-signing trust-root — are **release-blocking for *public* release** only; they do not block personal use.
- **Windows = experimental / WSL** (macOS + Linux Tier 1; WSL inherits the Linux work for free; light native guards only — no native PowerShell OSC, no signed MSI).

## Cross-phase rules (apply to every phase)

**Guardrails (restated from `docs/GOAL.md` — load-bearing):**
1. **Branch + PR only.** Never commit to `main`. Each phase → `feat/v5-*` branch(es).
2. **Tests + build gate.** No item is done unless `bun test` (engine), `tsc` + `vite build` (desktop), `cargo check` (Rust) pass.
3. **Never destructive.** No force-push / `main` rewrite / deleting user data. Commits stay **`prabs0410`**; no AI co-author lines. (PRs still blocked until `gh auth login` as prabs0410; pushing branches is fine.)
4. **Adapter rule (Principle XI).** All Claude Code access via `ClaudeCodeAdapter` + SDK; no raw JSONL; no tight polling.
5. **Build-all-then-checklist (this goal's gate mode).** Build every automatable task across phases in order; never block the loop on a human gate — record it in the master checklist and continue. Exception: do not *publicly release* until the two release-blocking gates clear.
6. **Stop on repeated failure.** After 2 consecutive failed attempts on an item, STOP and leave a note.
7. **Keep docs honest (Principle IX) + founder-curation.** Put agent work in NEW files; flag (don't edit) `GOAL*.md`/`INDEX.md`/`state.md`/`AGENTS.md`.
8. **Felt-improvement + secure-by-default (Principle II).** Every surface genuinely functional, not decorative; every remote/crypto default fails safe.

**Cross-phase dependencies (respect even in me-first order):**
- **Keep-awake is built once.** Phase 5 (Story 5.3) ships the cross-platform `keep_awake.rs` abstraction + the macOS `caffeinate` backend; Phase 6 (Story 6.2) only adds the Linux `systemd-inhibit` backend behind that interface; Windows is a graceful no-op. Do not re-architect it.
- **Tailscale binary resolver is one source.** The `tailscale_ip` candidate-path list (Phase 6 / 6.3.2 adds Windows paths) is reused by the Phase 5 Serve helper — not duplicated.
- **Transport encryption vs app-layer E2E.** Phase 5 ships remote transport relying on Tailscale's own WireGuard encryption (fine for your own tailnet). Phase 3 then adds app-layer E2E **and** the "refuse non-loopback bind unless E2E active" gate (3.2.3); once Phase 3 lands, E2E is the default path so the gate passes. Until Phase 3, remote bind leans on the transport — acceptable for personal use, **not** for public release.
- **The deferred Phase-2 security LOWs live here:** fail-closed input-bridge reconnect (3.3.1) + lifecycle audit logging (3.3.2) in Phase 3; the `TERMINAL_ONLY_METHODS` tier (7.2.1) + the exhaustive-classification build gate (7.2.2) in Phase 7.

# Phase 3 — App-layer end-to-end encryption  ·  me-first #3  ·  branch `feat/v5-crypto`

Wrap the engine↔phone stream in an app-layer AEAD session so the transport never sees plaintext. The pair code becomes a **SPAKE2 PAKE password** seeding a **Noise handshake** whose **ChaCha20-Poly1305** key seals the existing first-message auth + `/ws` + `/term-ws` frames. The scoped-bearer/`PairingService` model stays *inside* the tunnel. Two hard rules: **AEAD only — never unauthenticated AES-CTR** (sshx's mistake); loopback bridges (`/pane-bridge`, `/pane-input-bridge`) stay bearer-only and may stay cleartext on localhost (crypto scopes to the phone-facing sockets). Design: `docs/design/secure-mirror-tech-stack.md`.

### Story 3.0 — Crypto foundations & the library decision (de-risk first)
**Task 3.0.1 — Verify mobile X25519/ChaCha20-Poly1305, then pick the browser backend** [🔨 — small code, but device-gated] · Capability probe + recorded decision (WebCrypto vs libsodium-WASM). · *Files:* new `crypto/capabilities.ts` (`probeX25519()` via `crypto.subtle`); run on a real device via the cockpit; new `docs/design/phase3-crypto-decision.md`. · *Sub:* a) probe in Bun; b) probe on iOS Safari + Android Chrome; c) record pick + fallback trigger. · *Verify:* unit-test the probe never throws on missing API (automatable); the device result is the human gate below. · *Review:* founder sign-off before 3.2 wire work. · **[HUMAN-GATE (blocks 3.2 wire work): run the probe on physical iOS + Android — CI-impossible; the loop flags-and-skips 3.2+ until you provide the result.]** · **[FOUNDER-DECISION: default WebCrypto iff mobile X25519 confirmed both targets, else libsodium-WASM (`emilbayes/noise-protocol`).]**
