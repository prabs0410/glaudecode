## Verdict

The V5 RCE core is **architecturally sound where it counts**: keystrokes reach a PTY only through the
engine's scope+armed+live-token gate **and** an independent authoritative re-check in the Rust core;
the bearer/paired-token auth boundary on the bridges is correct; tokens are first-message-only and
never (intentionally) in the URL. **The danger is not the gate — it is everything wrapped around it.**
The recurring pattern is safety controls and security-relevant errors that **fail silently or
misleadingly**: the kill switch can report "disarmed" while Rust is still armed; the arm UI (and the
kill switch) vanishes on a routine WebView reload while phone input keeps flowing; revoked `/ws`
devices keep streaming live bash commands; `termPage`'s missing `r.ok` check turns a lost token into a
confident "not armed" lie. With zero tests on the authoritative Rust gate and zero tests on the
WebView safety UI, a regression in the most important code would ship green.

**Single most important fix:** make the arm/kill safety surface **trustworthy and authoritative
end-to-end** — hydrate the WebView's armed set from Rust (and keep the kill switch always reachable),
make `killSwitch`/`toggleArm` surface failures instead of swallowing them, extend the 2s revoke sweep
to the `/ws` approvals stream, and add a persistent global "remote ON / N panes armed" indicator — so
the UI can never claim "safe" while the machine is live to remote code execution.

## Cross-cutting themes

1. **The gate is fine; the safety affordances around it are unreliable** — kill switch can no-op, arm UI desyncs from Rust on reload, no persistent global indicator.
2. **Silent error-swallowing on the input/security path** — empty catches + missing `r.ok` turn auth-loss/scope-errors/failed-security-actions into invisible (often misleading) degradations.
3. **"Token never in the URL" is broken in exactly one place** — `cockpit.ts ?token=`, on the RCE-class credential.
4. **Engine↔served-page mirror drift is unguarded** — `ctrlByte`/`wrapForPaste`/`filterSessions` hand-duplicated with no test pin; the paste wrapper diverges from `handoff.ts` (no `201~` scrub); Rust-vs-engine bridge codec diverges.
5. **Test gaps concentrate on the highest-risk new code** — zero Rust tests on the authoritative gate + hostile-input decoder, zero WebView tests (no runner) on the arm/kill/consent UI, write-only audit log.
6. **Missing bounds/throttle on the RCE channel** — no rate-limit/size-cap on INPUT, no cols/rows clamp on RESIZE (0x0 reaches the real PTY), no WS-auth throttle, `/pair` per-IP limit collapses to one loopback bucket behind Tailscale Serve.
7. **Lifecycle/teardown asymmetry on exit** — engine child killed but Serve `:443` rule left registered, PTY children not killed, hook-strip ignores its write Result, no engine liveness/respawn.
8. **Consent decoupled from the dangerous capability** — the once-ever RCE consent gates the remote *toggle*, not the terminal-scope pair-code mint or pane arming.
9. **Supply-chain controls documented but not enforced** — the release workflow can publish an unsigned, auto-updatable binary (no signing-key guard); `id-token:write` with no attestation; broken SBOM; no frozen lockfile.

## HIGH (4) — independently verified against the real code

### H1 · `packages/engine/src/cockpit.ts:76` · security
**Cockpit accepts a paired (RCE-scope) token from the `?token=` URL query and never strips it.**
`let TOKEN = new URLSearchParams(location.search).get("token") || sessionStorage.getItem("ck.token") || "";` seeds from the query first. A paired token is bearer-equivalent (RCE-capable for terminal scope). `?token=` leaks it into history, the Tailscale Serve TLS-proxy access logs (the *recommended* transport), and the Referer on every sub-resource fetch. Unlike the `#code=` path (scrubbed via `history.replaceState`, lines 111-116), the `?token=` value is never removed — and line 113's rewrite is `location.pathname + location.search`, deliberately **preserving** the query. Contradicts the invariant stated all over the codebase. (Also breaks the flow: a token entered this way is never written to sessionStorage, so `ck.scope` is unset and every terminal link bounces to `/app`.)
**Fix:** delete the query branch → `let TOKEN = sessionStorage.getItem("ck.token") || "";`. If a deep-link is ever needed, persist to sessionStorage + `history.replaceState(null,"",location.pathname)` *before* any fetch/WS, and drop `location.search` from the line-113 scrub. Add a test asserting `COCKPIT_HTML` has no `location.search` token read and no token survives in `location` after load.

### H2 · `packages/desktop/src/Workspace.tsx:89` · bug
**Arm-state UI desyncs from the authoritative Rust core on any WebView reload — UI shows "disarmed"/hides the kill switch while phone input still flows.**
`armed` is `useState(new Set())`, reseeded empty on every mount and only mutated by clicks. The authoritative set lives in the long-lived Rust process (`PtyRegistry.armed`, gating `pty_write_internal`); it survives a WebView reload (vite HMR, ErrorBoundary remount, any refresh re-runs the WebView **without** respawning Rust/engine). After a reload, a pane still ARMED in Rust (still accepting keystrokes) renders 📱 OFF, and the kill switch (`{armed.size > 0 && …}`) **disappears entirely**. No `pty_list_armed` read-back exists. Defeats the core safety affordance.
**Fix:** add a `pty_list_armed` Tauri command returning `registry.armed` as `Vec<String>`; export `listArmed()` in `engine.ts`; hydrate `armed` in a Workspace mount effect (+ on focus/visibilitychange). Belt-and-suspenders: `app.emit("armed-changed", ids)` from `pty_set_armed`/`pty_disarm_all`/`pty_kill`. At minimum keep the kill switch reachable when local `armed` is empty, or fail-safe-disarm in Rust on a fresh WebView handshake.

### H3 · `packages/engine/src/server.ts:425` · security
**Revocation/expiry sweep covers `/term-ws` but NOT the `/ws` approvals stream — a revoked device keeps receiving live tool commands.**
The 2s sweep iterates only `termSockets` and force-closes invalid-token sockets. The `sockets` set (the `/ws` approvals stream) is verified only at first-message auth; nothing re-verifies it, and the sweep uses `sockets` solely to *push* frames. So after revoke/expiry, a `/ws` socket keeps receiving `frameEvent("approvals", approvals.list(), …)` every 2s — carrying `tool`, full `input` (the exact Bash command + paths), `sessionId`. "Revoke cuts the live session" holds only for the mirror, not the more sensitive approvals feed. No `/ws` revocation test.
**Fix:** in the sweep, before pushing, iterate `sockets` and apply the same revoke/expiry check + close (4003); skip pushing to a closed socket. Add a `/ws` revocation test.

### H4 · `packages/engine/src/termInput.ts:8` · security
**Bracketed-paste wrapper does not strip an embedded end-paste sequence (`\x1b[201~`) — paste-jacking from saved prompts.**
`wrapForPaste` wraps as `\e[200~${text}\e[201~` (mirrored verbatim in `termPage.ts:259`) but never strips a `\e[201~` already inside `text` — the PTY then terminates the paste early and runs the remainder as live keystrokes (the exact break-out `handoff.ts` guards against with `stripControl`). Concrete vector: the Smart-tab snippet button (`sendText(wrapForPaste(r.result.body))`) pastes a saved prompt file (`~/.glaudecode/prompts`, editable/synced by any process). Also reachable via the typed textarea, and the desktop clipboard paste (`TerminalPane.tsx:213`) shares the raw pattern.
**Fix:** strip interior markers before wrapping, in **both** the engine helper and its byte-identical `termPage.ts` mirror: `const clean = text.replace(/\x1b\[20[01]~/g, ""); return clean.includes("\n") ? \`\x1b[200~${clean}\x1b[201~\` : clean;`. Apply at `TerminalPane.tsx:213` too. Add a unit test (a body containing `201~` can't terminate the paste) + a mirror-equivalence test.
